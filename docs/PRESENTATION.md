## 1. Проблема

**Сейчас на Drive2 поиск работает по ключевым словам:**

Пользователь вводит запрос → получает **список статей**, где встречаются эти слова.

**Что не так:**
- Пользователь ищет **ответ**, а не список статей.
- «Какую резину советуют на Kia Rio?» → 50 статей, читать 2 часа.
- Мнения разбросаны по десяткам постов и сотням комментариев.
- Новичок не знает, какие статьи заслуживают доверия.

**Реальный пример:** поиск «аккумулятор Kia Rio» на Drive2 → **172 статьи, 3294 комментария**. Никто не будет это читать целиком.

---

## 2. Идея решения

**AI-помощник, который читает статьи за пользователя.**

Вместо списка — **аналитический ответ**, синтезированный из опыта авторов:

> **Вопрос:** «Какую резину советуют на Kia Rio?»
>
> **Ответ:**
> - Hankook Winter IPike RS W419 — мягкая, тихая, шипы
> - Nokian Nordman 5 — хорошо держит лёд и асфальт
> - Michelin X-Ice North 4 — топ по отзывам
> - Размер: 185/65 R15
> - Мнения авторов расходятся: одни за шипы, другие за липучку
>
> **Источники:** 5 статей Drive2 (ссылки)

## 3. Демонстрация

**Примеры работы** (можно показать вживую):

| Вопрос | Что получает пользователь |
|---|---|
| «Какую резину советуют на Kia Rio?» | Список моделей + размеры + мнения |
| «Сравни Michelin и Nokian — что лучше?» | Сравнение по характеристикам |
| «Как подключить подогрев сидений к сигнализации?» | Схемы, микросхемы, опыт авторов |
| «Какой аккумулятор купить на Kia Rio 4G?» | Модели, размеры, цены |

**Каждый ответ:**
- Структурирован (вывод → конкретика → нюансы)
- Указывает источники (проверяемые ссылки на Drive2)
- Честно говорит: «мнения авторов расходятся», если так и есть

---

## 4. Как это работает

**RAG — Retrieval-Augmented Generation:**

```
Вопрос пользователя
    ↓
[1] Эмбеддинг вопроса (multilingual-e5-small)
    ↓
[2] Поиск релевантных фрагментов в ChromaDB
    ↓
[3] Передача топ-7 чанков в LLM (Qwen2.5)
    ↓
[4] Генерация ответа + список источников
```

**Ключевое:**
- **Не выдумывает** — опирается только на статьи Drive2.
- **Честно молчит** — если информации нет, говорит прямо.
- **Указывает источники** — пользователь может проверить.

## 5. Технологии

**Всё open-source, работает локально:**

| Компонент | Что используется |
|---|---|
| Сбор данных | Playwright (headless Chromium) |
| Парсинг HTML | BeautifulSoup |
| Эмбеддинги | intfloat/multilingual-e5-small |
| Векторная БД | ChromaDB |
| LLM | Qwen2.5 (3b или 7b) |
| Веб-интерфейс | Streamlit |
| Язык | Python 3.12 |

**Никаких платных API. Никаких данных в облаке.**

## 7. Скорость и качество

**Два режима работы:**

| Режим | Модель | Время ответа | Качество |
|---|---|---|---|
| ⚡ Быстро | Qwen2.5:3b | 20–40 сек | базовое |
| 🎯 Качественно | Qwen2.5:7b | 1–3 мин | глубокое |

**На GPU (если развернуть на инфраструктуре Drive2):**
- 3b → **2–5 секунд**
- 7b → **5–10 секунд**

**Архитектура готова к масштабированию.**

## 8. Что мы предлагаем Drive2

**Не «серый» парсер, а полноценный продукт для интеграции.**

### Вариант 1. Официальный API

- Вы даёте нам **API-доступ** к статьям и комментариям.
- Мы индексируем **всю базу** Drive2.
- Результат: **AI-поиск** по всему сайту.

### Вариант 2. Размещение у вас

- Мы разворачиваем систему **на вашей инфраструктуре**.
- PostgreSQL + pgvector вместо ChromaDB.
- GPU-сервер для быстрых ответов.

### Вариант 3. Гибрид

- Мы оставляем прототип у себя для тестирования.
- Вы тестируете на своих данных.
- Совместная доработка.

## 9. Что нужно от Drive2

**Минимально:**

1. **Технический фидбек** — насколько идея полезна.

**Идеально:**

4. **GPU-сервер** или облако — для скорости.
5. **Команда** для совместной доработки.
6. **Юридическое согласование** — использование данных пользователей.
